# 示教准备与样条编辑调整

目标：按本轮用户修正，趴着或站着都可点击准备；趴着自动站起、等站稳再定位，自检通过后可开始录制。地图编辑用稀疏控制点生成真实样条，录制结束已有平滑步骤需在平台明确展示。

范围：本地实现、假ROS/浏览器与相称算法检查，完成后两个仓库各提交一次；不部署、不push、不在真机上发站起/解锁/运动、不启动训练。产品中点击准备触发自动站起是本轮明确要求，替代先前人工站立前提。遥控行走仍由用户操作，定位通过不自动行走。

## 选定实现

1. 准备复用已有`stand_up`，保留温度/急停/状态/ready检查；站起完成才启栈/载图、定位，最终验证站立状态。准备过程绑定请求页面并检查中断，断开或急停后不能继续发后续站立阶段或定位。页面允许初始趴姿，展示“站起→地图→定位→可录制”。
2. 编辑采用按弦长参数化的插值三次样条（SciPy现有依赖），生成间距≤0.05m的导航折线；控制点可稀疏，两个点退化直线。样条拐弯/过冲也必须通过完整足迹检查，不能只检查点或点击点的直线。断段不自动串接，控制点与最终稠密结果分开保存，重开编辑器继续编辑控制点。
3. 用后端预览保证屏幕曲线与保存处理同源。`POST /api/taught/maps/{name}/preview` 接收 `{expected_revision,map_token,points}`，不写地图、不调用运动；返回 `{ok,msg,data:{map,revision,map_token,control_points,preview_points,processing,executable,report}}`。非法/碰撞返回明确原因，仍尽可能给几何预览；过期响应不能覆盖新拖动/换图。
4. `TeachingRepository`共用构建方法供preview/save：手绘→样条采样→完整足迹复验；调用原处理器时将额外平滑偏移设为0，避免移动坐标后仍沿用原曲线切线。录制→原加密/平滑→足迹校验，追加/替换继续保护旧区间外点。`reference.editing.control_points`保存编辑控制点，活动points始终为最终结果。
5. `doc.processing`返回实际处理摘要（输入点数/结果点数、插值方法、平滑最大调整米数/迭代、足迹结果）。结束按钮改为“结束并平滑保存”，处理中和完成后显示平滑步骤/结果；没有调整时如实显示无需调整，不增加冗余手动优化步骤。

## 共享接口与分工

核心新增`go2w_taught_route.spline.interpolate_control_points(points, *, spacing=.05, max_points=20000) -> (dense_points, meta)`，dense点含x/y/yaw、continuous_id、fixed/control_index；按连续段独立处理，拒绝坏数值、相邻重复和退化方向，限制输出数量。meta含method/degree/control_count/output_count；调用方保留原始控制点及来源。

网页 GET 文档加`control_points`（旧文件回退到原points）、`processing`；预览返回最终`preview_points`。HTTP与WS保存继续使用points作为编辑控制点；采集finish内部明确走recorded模式，不能把原始测量改造成手绘样条。

- 核心包：样条数学与边界测试；不改网页。
- 静态页面：准备流程文案、样条后端预览/稀疏控制点编辑、平滑结果显示与JS/浏览器验证；不改服务端。
- root：准备状态机、仓储/preview协议、实际平滑摘要、文档与集成。
