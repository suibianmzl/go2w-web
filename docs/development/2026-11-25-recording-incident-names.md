# 手动包与自动异常包的区分

用户先报告“录制当前数据”后出现两个包，随后要求给“导航失败”和“长时受阻”的自动包增加名称标签。核对窗口差异后，用户明确选择“只给自动包加标签，保留独立自动包”。本次只调整新自动包的名称，保留两种记录窗口和自动保存策略。

## 已核对的真机证据

从 `.30` 只读检查用户截图对应的两个目录，当时运行 Web v1.2.5：

- `go2w-02_trigger_1125_153540_r/capture.json` 的请求编号为 `1795592140890-99c3898d404a98`，点击时刻为 `1795592140919228025 ns`，固定窗口为 `1795592120919228025` 至 `1795592150919228025 ns`，即点击前20秒＋后10秒。
- `go2w-02_1125_153558/incidents.json` 包含“长时受阻”和“导航失败”两条异常，属于后台自动保存；没有第二条手动 capture 请求。
- 长时受阻记录的 `ts=1795592135650 ms` 已按 `ago=8秒` 回推，不能直接当作自动存包触发时刻。它的结束时刻 `1795592151988 ms` 晚于手动窗口结束约1.07秒。自动包还覆盖手动包结束后的异常数据，直接合并会改变可观察范围。

## 名称规则与验证

- `stuck` → `_longstop_`；`nav_fail` → `_navfail_`；两者合并时按固定顺序使用 `_longstop_navfail_`。
- 手动 `_trigger_`、其他自动类型、存包时机和窗口保持原行为。
- 通过真实后端存包请求测试单一/组合标签、顺序稳定性、同秒重名及30字符狗编号，名称均须满足现有48字符安全限制。
- 通过自动异常调度测试，确认合并到同一包的全部原因都传给命名逻辑，异常记录与包目录的匹配不变。
