# 手机录包与语音备注

## 已确认需求与设计

- 控制台按钮及 Shift+Enter：保存点击前20秒、后10秒的数据，每次操作生成一个包。
- 同次操作使用当前电脑/手机麦克风录语音备注，默认5秒，可调1–20秒，随包落盘并可播放。
- `/record` 独立页面：只展示录包结果、必要状态与时长设置、底部中央相机式按钮。
- 复用现有回溯保存和原生JS，不引入前端依赖。后10秒由后端等待，浏览器断线不取消保存。录包请求绑定固定结束时间，避免轮询延迟移动窗口；缓存增加5秒余量，字节上限保留。
- 语音从点击后开始，首次授权可延后开始；录音失败不能阻止数据包保存。上传失败保留本地录音供重试/下载。
- 手机经局域网访问，麦克风需要受信任HTTPS。增加服务TLS证书参数；证书安装/手机信任、远端部署不在本次本地维护授权内。
- 当前共享工作区已有资料库与回放修改，保留原样，仅提交本次改动块。不触发运动、训练、远端部署或push。

## 实施顺序

1. 先验证固定时间窗口和保存协议，扩展Python/C++回溯快照、后端后10秒等待及返回包名。保护异常自动保存的旧调用。
2. 为语音存取写HTTP边界测试，再实现同包音频接口，限制路径、格式、大小与时长，拒绝覆盖。
3. 实现共享录音控制、快捷键、控制台设置与独立手机页；覆盖重复触发、输入框、权限拒绝、断线及上传失败。
4. 用本地隔离HTTP服务及Chrome虚拟麦克风核对真实录音、上传、回放、默认/边界时长和375px/横屏布局；核对TLS启动参数；按本任务文件/改动块commit。

## 验收与边界

- 时间窗口红→绿测试：固定t=40秒点击，结束t=50秒，只保留t=20..50秒；延后处理不纳入t>50秒。
- HTTP测试：录音落在正确包，回读一致；缺包/未完成包、越界路径、错误容器签名、声明时长超限、过大及不同内容覆盖被拒绝。同内容重试返回成功；受限大小与文件头检查不解码音轨，实际可播放性/时长由Chrome录音回读验证。
- 浏览器：一个点击/快捷键对应一个请求；显示收集后10秒/录音倒计时，保存完成后可再次按下；语音失败明确显示，数据包仍保存。
- 真实手机HTTPS信任、真机ROS录包与ARM64整包构建独立验收，本地软件结果不替代实机证据。

## 实施与复核记录

- 后端接收点击请求后等待10秒；Python/C++按指定结束时刻截取30秒。手动包使用`_r`后缀隔离普通分段命名。点击请求ID先写入`.captures`，WebSocket回执丢失后可按ID找回已完成包。
- 语音先在浏览器录制，完成后上传到确切包名。相同内容重试幂等成功；不同内容拒绝覆盖；元数据不跟随已有符号链接。服务只验证容器签名、声明时长和大小，不新增媒体解码依赖。
- 异常保存保留原规则，将互斥等待上限覆盖手动10秒采集和20秒写盘预算；缓存与字节上限仍可能缩短实际数据，结果显示实际时长，不把请求窗口当作实收长度。
- 本地证据：12项Python测试、Node录音控制测试、既有回溯/分段/异常/进程管理/示教/原生回放回归通过。Chrome实录5/1/20秒、刷新回读、375px竖屏/横屏/平板、HTTP录音降级通过；强制关闭真实WebSocket后继续录音，7次按ID查询后成功关联。新增结果保持已有播放器与播放进度，已由真实Chrome红→绿核对。临时受信证书的真实HTTPS入口回读通过。C++在本地amd64 ROS Humble镜像编译及`--self-check`通过。
- 浏览器联调产物：`/tmp/go2w-recording-browser/`；服务与测试日志：`/tmp/go2w-recording-*.log`；C++二进制仅在`/tmp/go2w-recording-build/`，不提交、不远端部署。
