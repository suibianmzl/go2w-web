# 地图与示教轨迹

每张保存地图只有一条活动示教轨迹。采集成功或编辑保存通过后，它立即成为这张地图的参考；以后从网页正常下发导航任务，无需再选路线名、修订号或执行 `execute`。

## 先录一条轨迹

1. 右上角选择 **示教采集**，选择已保存地图。机器人趴着或站着都可以，不需要提前手动站起。
2. 点 **准备示教**，在确认框确认周围空间已清空并点 **开始准备**。趴着时复用底盘的站起流程；已经站稳则直接进入静止检查。连续静止至少 2 秒后，才准备导航服务、加载所选地图并触发定位。页面依次显示站起、站稳、地图、定位和自检状态。期间不要操作遥控；移动后会重新计时。准备不会自动解锁遥控、开始录制或下发导航目标。
3. 如果定位失败，用已有的初始位姿工具在地图上修正位置，再点 **重新自检**。位置标准差需要不超过 0.3 米，激光与地图匹配率至少 60%；地图、测量时间、坐标变换及定位来源也必须有效。缺失项不会当成通过。
4. 首次保持 **整条替换（无轨迹时创建）**，确认 **开始采集**。随后点 **键盘遥控**，按已有遥控提示操作机器狗走路线。开始记录不会自动让狗运动。
5. 中央地图以琥珀虚线显示已保存参考，以亮线显示本次采样；暂停或中断的位置保留断口。右栏显示点数、长度及状态。左栏的 **示教轨迹** 开关控制当前地图的显示。
6. 点 **暂停采集** 会停止遥控、上锁并保留草稿；点 **结束并平滑保存** 会停止采样，自动重采样、平滑，再检查连续性和整个机器人轮廓扫过的区域。通过才替换活动参考；失败保留旧参考及原始草稿。

自检完成后，右栏用绿色结果框突出 **自检通过**，八个检测项以两列短标签和状态图标显示。绿色勾表示通过，红色警示表示未通过，灰色时钟表示待确认；具体数值和条件可展开 **检测详情** 查看。未通过的原因会直接显示。

通过后 **准备示教** 改为灰色 **已准备**，可以直接开始采集。趴下、急停、换图或检查失效后允许重新准备；仍可使用 **重新自检** 核对当前状态。断线或被后端作废的旧结果不会继续显示成当前通过状态。

取消准备、急停、切换任务或控制页断开，会使本次准备失效，不再继续后续站起或定位阶段。取消不会撤销已经发出的底盘动作，也不代替单独的趴下操作；重新准备须等前一次操作结束。

**平滑在“结束并平滑保存”中自动触发，不需要再找一个优化按钮。** 处理中右栏会显示“加密采样、平滑路线、完整机器人足迹检查”；保存后显示实际输入/输出点数、最大调整距离、迭代次数和完整足迹检查结果。最大调整为零时显示“无需调整”，不能据此判断没有执行处理。原始采样日志仍保留，可用于核对处理前后的差异。

原始采样按实际测量时间记录 map 位姿及 odom 位姿。显示用的里程轨迹不是示教数据；网页也不会把最新定位修正套到历史采样上。

## 暂停、断线与续采

- 浏览器控制页断开、心跳丢失、定位失效、测量不连续、换图或切换运行档位，会中断采集。旁观页断开不影响控制页。
- 原始保留点逐点落盘。后端进程强制退出后，重启能恢复已经确认的点，但只恢复成 **采集中断**，不会自动继续采样或运动。
- 回到原地图的示教页。如服务也已停止，可先重新加载同一地图并定位；草稿编号不变。明确遥控回到最后断点附近，静止后点 **继续采集**。
- 继续前重新自检；当前位置与断点须在 0.2 米内，短连接也须通过足迹检查。该连接会标为人工确认的连接，原始日志的两个连续段保持不变。
- 点数不足时可以继续采集。几何或版本冲突导致校验失败时，可点 **在编辑器中修复草稿**；原始数据保留。也可以放弃草稿重新采集，放弃不删除原有效参考。

## 更新已有轨迹

| 方式 | 从哪里开始 | 保存后结果 |
| --- | --- | --- |
| 整条替换 | 新路线起点 | 用校验通过的新采样替换整条参考 |
| 末尾追加 | 旧轨迹末端 0.2 米内 | 保留旧参考的全部点，在末端接入新段 |
| 替换选中区间 | 选定起点 0.2 米内 | 走到选定终点 0.2 米内；只替换区间，区间外原点和朝向保留 |

区间可输入点序号，也可在中央地图先点起点、再点终点。开始采集后地图、模式和区间锁定，避免用另一条基线保存。即使锚点重合，机器人转身所需的空间也会检查。

## 直接在地图上编辑

从示教页或左侧示教图层点编辑入口；独立地址是 **`/taught-editor?map=地图名`**。

1. 选地图。它只读已保存文件，不切换机器人正在使用的地图，不建立运动控制连接。
2. 没有参考时点 **新建轨迹**，用 **绘制 / 加点** 按行进顺序放少量控制点，主要放在起点、弯道和终点，不需要像录制一样密集。两个点连接为直线，三个及以上控制点生成经过这些点的三次样条；闭合路线首尾同位置时使用闭合样条。
3. 用 **选择 / 拖点** 调整位置；也可输入 x、y 米坐标，插入、删除点，选连续区间并撤销/重做。圆点和灰虚线只表示控制点及顺序，**青色实线才是后端生成的路线预览**，琥珀虚线是已保存参考。修改后自动重新生成预览。
4. 可以旋转显示、缩放和平移地图。保存坐标始终是地图世界坐标，显示旋转不会改变底图或路线坐标系。
5. 等当前预览通过，再点 **校验并保存**。预览与保存共用后端处理，生成相邻距离不超过 5 厘米的导航点，并检查完整机器人足迹。样条可能向弯道外侧偏出，所以检查的是曲线而非控制点间的直线；碰撞时显示红色曲线、禁止保存，需要移动或补充控制点。通过后更新这张地图的唯一活动参考并增加修订。
6. 刷新后仍编辑原来的少量控制点，导航使用已保存的稠密结果。样条本身已平滑，不再额外移动曲线上的点；页面显示“三次样条生成／无需额外调整”。这是与录制数据的重采样和平滑不同的处理入口。

同一张图被另一页先保存，或底图在编辑期间改变时，本页保存会拒绝覆盖，草稿和撤销历史保留。重新读取可采用最新参考；也可先导出当前草稿再整理。保存失败不能理解为新参考已生效。

编辑器中的线是人工编辑几何；恢复入口中的点是原始采样草稿，两者来源有记录。原始断段不会自动冒充实测连续路程；出现断口时须点 **连接断口…** 并确认，连接可以撤销，之后仍须整体通过校验。旧版本没有保存控制点的参考会按原点加载，不自动抽稀；新编辑保存的路线会分别保留控制点与最终结果。

## 文件如何对应

以地图 `lab` 为例，实际数据根由 `GO2W_DATA` 决定：

```text
data/maps/lab.yaml              地图配置 + go2w_taught_route 唯一活动参考
data/maps/lab.pgm               原有地图图像
data/maps/lab.taught/versions/  不可变历史修订
data/maps/lab.taught/captures/  每次采集的原始日志和恢复检查点
data/routes/                   导航派生缓存，可由地图包络重新生成
data/routes.json                原有多站导航任务，与示教参考分开
```

因此**示教已经和地图配置写在同一个 YAML 文件中，一一对应**；地图图像仍保留标准 PGM 文件，兼容现有 map_server。备份地图时至少一起备份 YAML 和 PGM；需要历史和断点恢复时连同同名 `.taught` 目录备份。

地图 YAML 的 `go2w_taught_route.reference.points` 是导航使用的最终点；手绘路线的 `reference.editing.control_points` 保留编辑控制点，`reference.processing` 保留实际处理摘要。录制的原始逐点测量放在 `.taught/captures/`，平滑不会覆盖这些原始测量。

当前支持标准 trinary 地图与最大灰度 255 的 P2/P5 PGM。非此格式会明确报错；不会把不能核对的地图当成空轨迹。对栅格编辑另存或旋转导出的新地图，不直接继承原图活动示教，需在新图重新校验保存；原图不变。回收地图会连同 `.taught` 目录移动，有未结束采集的地图禁止删除。

已接受的导航任务固定本次地图和参考修订。导航中编辑保存只影响后续任务；不会在半路突然切成新线。新版网页启动导航时启用配套示教代理；旧服务已运行时，在普通任务的现有出发流程中完成启用和重新定位，无需手动 `execute`。

## 本地开发与验证入口

生产运行需同时使用本次 `go2w` 导航包与网页版本。算法包不可用时会明确提示，不能仅更新静态页面就认为导航已支持。

```bash
# 读取地图副本、假机器人；导航源码默认位于 ../go2w/src/navigation/go2w_taught_route
GO2W_MAPS_SRC=/path/to/maps dev/run.sh

# 文件/恢复/异步生命周期测试：开发venv要有numpy、scipy、PyYAML、aiohttp
python -m unittest discover -s dev -p 'test_teaching*.py'

# 独立假ROS后端：自动创建临时地图、SIGKILL后重启并验证真实HTTP/WS
python dev/check_teaching_protocol.py --output /tmp/taught-protocol-new

# 趴姿和站姿分别检查；每次使用新的证据目录
python dev/check_teaching_protocol.py --output /tmp/taught-passive-new --initial-posture Passive
python dev/check_teaching_protocol.py --output /tmp/taught-standing-new --initial-posture Velocity
```

`--output` 应使用新的测试目录；这些检查均不能替代真机定位、轮腿控制、网络中断及性能验收。协议、文件和浏览器的实现约定见 [开发设计](development/2026-11-18-taught-route-workspace.md) 与 [本轮准备/样条调整](development/2026-11-19-taught-prepare-spline-refinement.md)。
