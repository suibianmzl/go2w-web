# 导航站点强制跨越

目标：在 `dhb/param_api` 的站点编辑器增加“强制跨越”。可以全不选，或者选择至少两个站点；按路线顺序，第一个选中站到达后设置 false，最后一个选中站到达后设置 true。其间未选中点也在同一区间，不生成多个区间。

工作位置：独立克隆 `/home/tink/program/go2w-web-force-crossing`，基线 `111591427aa1a5fd84bbbad1995018894506526a`，分支 `dhb/param_api`。原工程只读。仅授权本地开发、假机器人验证和 commit，不部署、不连接机器狗；后续用户已授权推送到原远端分支 dhb/param_api。

## 实施选择

- 浏览器按进度发 HTTP：浏览器断线会漏掉恢复，故不采用。
- 后端任务请求自身 HTTP：需额外处理监听端口、TLS和停服顺序，增加同进程调用链。
- 采用后端任务与既有 HTTP 路由共用异步参数设置函数。保留两个 HTTP 路由、同源限制、返回字段和超时；不调用 HTTP handler 方法。按用户更正的映射：强制跨越对应 ObstaclesCritic.enabled=false，正常避障和异常恢复对应 true；原HTTP入口的字面参数值保持原义。

站点字段 `forceCrossing: true`，未选中不存字段，未配置跨越的路线也在从头启动时先初始化正常避障。前后端均拒绝只选一个点以及非布尔值。编辑、插入、删除、排序和保存保持字段归属；更改区间会使旧断点失效。

逐站和连续通过共用到点切换函数。首尾边界需要完成现有到达确认，不使用提前经过判断；连续通过在边界处分段，参数设置完成后才下发下一段。其他站点保留原通过、停留和播报规则。循环每圈重新启闭，最终返回起点不重新开启。断点接续目标在区间内部时，先重新开启再出发；区间前后保持关闭。

异常规则（用户已确认）：任务取消、失败或设置失败时停止后续导航；只要本任务曾尝试开启且尚未成功关闭，在退出时尝试 true；失败显示明确原因。正常关闭失败不得报告任务成功。突然断电或进程被强杀无法保证执行恢复，文档明确边界。参数接口仍只证明 ROS 命令成功，不额外读回节点值。

验收：数据校验和旧路线兼容；真实任务协程的逐站/连续通过、首点已在附近、循环、接续、取消、启闭失败；HTTP现有回归；Chrome编辑保存重载、单选拦截和排序保留。全部使用隔离假机器人/本地替身，不触发真机运动。

2026-11-25补充要求：所有从头启动的路线，必须先成功设置正常避障true才允许下发首个导航目标；包括无跨越标记和已在起点附近的路线。初始化失败则任务失败并尝试恢复，恢复仍失败时保留恢复门槛；取消不继续发目标。断点区间恢复规则保持原义，不因这项初始化改动把区间内接续误设成true。
