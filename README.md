# 网页控制台

替代 RViz 和 `nav.sh` 的网页界面。三栏布局：左边图层和 topic，中间地图，右边任务、运行档位、定位质量和底盘控制。

```
server/go2w_web.py   后端：rclpy 节点（域 43）+ aiohttp，HTTP 和 WebSocket 同一端口
server/procs.py      运行档位的进程管理（经运行容器 supervisor 的 socket 启停进程组）
server/camera.py     前置摄像头 RTP 组播接收、拼帧
server/mapmeta.py    地图续建：<name>.meta.json 读写、血缘、续建前置检查
server/mapcontinue.py 地图续建：起点位姿三级降级、图外检查、自检时的「还在起点吗」
tools/              随网页包部署的工具脚本（map_overlap_check.py 续建自检等；源在主仓库 scripts/calib）
static/              前端：原生 JS 模块，不需要构建
  js/source/mock.js  模拟数据源（示例地图 + 机器人仿真）
  js/source/ros.js   ROS 数据源（连后端 /ws）
dev/                 本地调试：假 ROS、假摄像头、协议测试
prototype/           最早的单文件原型和右栏原型，留作对照
```

界面只读 `js/store.js` 里的状态，两个数据源负责填它；操作统一经过 `js/actions.js` 做前置检查和确认。

## 和 go2w 主仓库的关系

这个仓库是从 [go2w](https://github.com/SinceJULY99/go2w) 的 `web/` 目录拆出来的（11-10，保留了历史）。代码本身单独维护，但运行时仍依赖主仓库：

- 11-12 起扩展坞跑的是统一运行容器 `go2w_runtime`（镜像 `go2w-runtime:<release>`，由 systemd 的 `go2w-runtime.service` 启动），不再有 `go2w_humble` / `go2w_web` 两个容器。网页打包在镜像里：后端 `/opt/go2w/console/server`，前端 `/opt/go2w/console/static`。
- 导航、巡逻、录包、回溯、速度桥都是容器里 supervisor 管的进程组，后端经 `/run/go2w/supervisor.sock`（环境变量 `GO2W_SUPERVISOR_SOCKET`）请求启停；运控 control 组和 DDS 录制不归网页管。
- 存图、对齐地图由后端直接起子进程，脚本在 `/opt/go2w/console/tools/`（`save_map.sh`、`align_map.py`）。
- 数据目录是容器里的 `/go2w/data`（扩展坞上 `/opt/go2w/data`），可以用 `GO2W_DATA` 改。地图、路线、录包都在那里，不进这个仓库。导航日志在 `data/logs/navigation.log`，遥控速度桥在 `data/logs/bridge.log`。

## 多点路线任务

1. 加载地图，点击工具栏的「导航点」（快捷键 4）。单击地图添加一站，或在站点按住拖出箭头，松开后保存箭头指向的到站朝向。右侧按顺序列出站点，可以给每站填名字。每条路线可包含 2–50 个点。
2. 用箭头调整顺序或用 × 删除点。点「确认路线」后，最后一站标为终点，只对未手动指定朝向的站点按路线推算默认方向。确认会请求 Nav2 检查站间路径，在地图上画出规划结果。可以先保存未检查的路线。
3. 输入名称并点「保存任务」。任务绑定当前地图。从列表选中后可修改或删除任务。需要运行时，从列表选中任务，在对应地图启动导航、确认定位并解锁底盘，再点「启动导航任务」。按钮下方会说明暂时不能启动的原因。
4. 出发前后端用当前位姿补算第一段，并重新检查整条路线。任何一段规划失败都不会出发。通过检查后，每站用一次 Nav2 导航，成功到达才派发下一站。任务卡片显示当前站和总站数，执行中失败会停止。

5. **循环：** 启动前勾选「循环」并填圈数。1 → 2 → … → 终点 → 1 算一圈：到终点后直接回 1 号点，不原路返回。回到 1 号点时按它自己的朝向停（自动朝向 = 面向 2 号点）。2 圈就是走两遍，下一圈从 2 号点出发；0 圈表示一直循环，直到取消。出发前检查一整圈，包括终点回 1 号点那一段。不勾选就是单程，停在终点。圈数只在启动时生效，不存进任务。
6. **从 1 号点附近出发：** 启动时离 1 号点不到 0.5 m，就当已经在 1 号点，直接去 2 号点（太短的路径 Go2W 容易卡住不动）。

网页上的 A/B 往返巡逻和地图工具栏的「导航目标」已移除（11-06），用多站任务代替：两个点加「循环」就是往返巡逻。命令行（`nav.sh`）启动的 `patrol.py` 后端仍会识别：取消、急停、切换档位时会连它一起停，它运行时网页拒绝启动多站任务。多点任务执行时，其他网页不能另发单点、巡逻或键盘遥控指令。取消、急停、上锁、控制方心跳丢失、切换地图或运行档位都会结束整条任务。连接恢复后不会自动继续。路线存在后端的 `data/routes.json`，和地图一样可单独备份。纯前端 `?mock` 的路线存于当前浏览器，没有 Nav2 规划检查。假 ROS 后端会把规划结果明确标为「本地模拟」。真实规划预览只代表检查时的地图与代价地图，执行中仍由 Nav2 根据最新障碍物重规划。

本地可用 `dev/run.sh` 启动假机器人，再运行 `node dev/test_routes.mjs` 验证多点协议和停止行为。真机验收时要检查实际到点、朝向和停车。

## 右栏任务流程（11-06）

右栏顶上是三个任务：**导航 | 重定位 | 建图**。点标签就是真的切换档位，切换时一律先停车（取消任务、底盘上锁）。原型见 `prototype/right_panel.html`。

- **导航**：没在跑时弹框选地图、确认站立静止，确认后直接启动导航。之后按五步走：地图 → 初始位置（用「初始位姿」工具，或确认 AMCL 当前位置正确）→ 导航任务（只列当前地图的任务，新建 / 编辑沿用原来的路线编辑器）→ 运行参数（循环、最大 vx / wz）→ 启动。「启动导航」弹确认框列出这次的设置，确认后后端先解锁再出发（`route_start` 带 `arm: true`，出发失败会把锁再上回去）。
- **重定位**：导航在跑时不重启导航栈，只取消任务、上锁；导航没在跑时启动「定位」档位。在 AMCL 当前估计的基础上手动微调：方向键按屏幕方向平移、Q / E 旋转（步长 1 cm·0.5° / 5 cm·1° / 20 cm·5°），或在地图上拖青色机器人平移、拖车头圆点旋转。激光按修正后的位姿重画，贴墙绿、悬空红，匹配率在前端实时算（和后端一样，离墙 0.10 m 内算对上）。点「应用到 AMCL」才发出，用小协方差（σ 5 cm / 2°，`initial_pose` 带 `cov: "fine"`）。有没应用的改动时离开会先问。偏得太远时用「重新给位置」走普通初始位姿。
- **建图**：确认站立静止后停掉导航、启动建图。五步：建图中（运行时长）→ 遥控走一圈（可勾选同时录包）→ 地图对齐（可选，从底部抽屉挪过来）→ 保存地图（默认名 `lab_年月日`，后端不覆盖同名，保存后自动换成 `_2`、`_3`…）→ 结束：「用这张图去导航…」（弹框里默认选刚保存的图）或「停止建图」。没保存就离开会提醒。底部抽屉「地图与录包」只留地图列表和录包管理。
- 原来的「运行档位」卡片只在调试模式显示。

## 摄像头

地图区里的摄像头浮窗显示 Go2W 前置摄像头：地图右上角按钮列最下面的摄像头按钮打开 / 关闭（默认关着），标题栏 ✕ 关闭；拖标题栏移动，拖右下角按画面比例缩放，双击右下角恢复默认（左下角、宽 320 px）；位置和大小记在本机浏览器 `localStorage` 的 `go2w.camWin`。只在浮窗开着且浏览器标签页在前台时传画面。主控 `192.168.123.161` 在机器狗内网组播 `230.1.1.1:1720`，格式为 RTP/H.264，1280×720，约 14 帧/秒，约 1.5 Mbit/s，约每 2 秒一个关键帧（11-06 在扩展坞上实测）。后端在扩展坞有线口上接收，只把 RTP 拼回完整帧，不解码，再经 `/ws` 原样转发。浏览器用 `js/vendor/jmuxer.min.js`（jmuxer 2.0.7，MIT）封装成 MSE 播放，http 页面就能用。

- 只有这个标签页开着、底部面板展开、浏览器标签页在前台时才传输。切走后后端退出组播，不再收任何数据。
- 同一时间只给一个网页传画面。别人在看时显示对方 IP，可以点「接管画面」。
- 打开后最多约 2 秒出画面（要等下一个关键帧）。网络跟不上时，画面会跳到下一个关键帧，延迟不会越积越多。
- 拖高底部面板可以看大一点，面板高度会被记住。
- 后端的接收地址和网口可以用环境变量 `GO2W_CAM_ADDR`（默认 `230.1.1.1:1720`）和 `GO2W_CAM_IF`（默认 `GO2W_WIRED_IF`）修改。

本地调试：`dev/run.sh` 会启动 `dev/fake_camera.py`，循环回放真机录的 10 s 样本 `dev/camera_sample.rtp`。测试：`dev/test_camera.py`（拆帧，装了 ffprobe 会独立解码核对），`dev/test_camera_ws.py`（协议，要先运行 run.sh）。

## 地图续建（11-17）

建图流程里的「续建已有地图」：在已有地图上继续采集，把新区域并进同一张图。只能加不能删——挪走的家具留下的旧墙线擦不掉，要刷新只能重建。完整方案在主仓库 `docs/地图续建.md`。

流程：选基准 → 检查基准（`cont_preflight`）→ 开始续建（`cont_start`）→ 自检（`cont_check`）→ 收工（`cont_finish`）。

- 基准图必须有 `.posegraph` + `.data`。续建永远另存新名字，基准图不动；收工时写 `<name>.meta.json`，`routes.json` 里指向基准的任务改指新图（坐标系不变，站点不用重标）。
- 开始续建：起点位姿按 停车点（`data/parkings.json`）→ 自动定位（在磁盘上的基准图上做）→ 手动 的顺序取，起点必须在基准图范围内；然后关扫描闸门、调 `/slam_toolbox/deserialize_map`（`START_AT_GIVEN_POSE`），只放一帧验证扫描，自检通过才恢复连续采集（v1.0.5 起，见下面「续建扫描闸门」）。
- 这个服务读文件失败也返回成功，所以**自检是唯一判据**，没通过不许存图。自检（11-17 起不用回起点）用 slam 当前位姿（TF `map→base_footprint`，还没有 map 坐标系时退回起点位姿），角度修正绕该位姿转（`--pivot`），超出 0.40 m / 8° 报「起点位姿偏了」，并把修正量换算成起点位姿（`start_fix`）供重来；贴合率 < 85% 报「环境和图对不上」，提示站到能看到旧墙的地方。
- 检查基准时核对运控策略（环境变量或 `runtime.env` 的 `GO2W_CONTROL_POLICY`）和切片高度（`pcl2scan_slam.yaml`，运行镜像里在 `/opt/go2w/base/go2w_bringup/share/go2w_bringup/config`），和基准 `meta.json` 不一致就拦下。

测试：`dev/test_map_overlap_check.py`、`dev/test_mapmeta.py`、`dev/test_mapcontinue.py`（不用起 run.sh）。

## 运控策略切换（11-17）

机器人卡片「姿态」下面的「策略」下拉框：**只有趴着（Passive）时能切**。后端（`set_policy`）经 supervisor 停掉 control 进程组，只换 `GO2W_CONTROL_POLICY` 再用同样的环境变量启动，然后最多等 20 s 收到新运控的 Passive（新进程先报一下 `Init`，不算异常）；收不到就自动切回原来的策略。`GO2W_CONTROL_CONFIG` 有值时拒绝切换。切换只在本次开机有效，重启扩展坞后回到 `runtime.env` 里的策略。当前策略（supervisor 里的实际值，拿不到再读 `runtime.env`）也用于地图续建的基准检查。

测试：`dev/test_procs.py`；`dev/test_policy.mjs`（先 `GO2W_FAKE_CTRL=Passive GO2W_FAKE_POLICY_FAIL=mjlab_go2w_cmd_m22 dev/run.sh`）。

## 电机温度（11-17）

后端每 5 s 临时订阅一帧 `/go2w/robot_lowstate`，不反序列化，按 CDR 偏移读电量和 16 个 `motor_state[i].temperature`（int8，℃，字节 `4 + 108 + 48·i`；0–11 是 右前 / 左前 / 右后 / 左后 × 髋 / 大腿 / 小腿，12–15 是轮子），状态里发 `motorTemp`，20 s 没读到就是 `null`。偏移用真机录包核对过：髋关节平时 46–67 ℃（低电量跑久了到过 81 ℃），大腿 / 小腿约 30 ℃，轮子约 23 ℃。

机器人卡片里「电机温度」一行显示最热的电机，点开是 4×4 的表。≥65 ℃ 黄、≥85 ℃ 红，并在地图上方提醒（只提醒，不拦出发）；阈值在 `static/js/util.js` 的 `MOTOR_WARN` / `MOTOR_CRIT`，是按实测定的保守值，不是宇树的保护温度。本地：`?mock&hot` 或 `GO2W_FAKE_MOTOR_TEMP=52,88,…（16 个）dev/run.sh` 看过热效果。

表上面的下拉（同 app「狗腿信息」）切换 **温度 / 错误标志 / 力矩**。错误标志读同一帧的 `motor_state[i].reserve[0]`（uint32，字节 `4 + 116 + 48·i`），状态里发 `motorInfo: {err: [16 个]}`；0 = 正常，非 0 标红显示十六进制，机器人卡片那一行变红写「N 个报错」（不进地图上方提醒）。用录包核对过：16 个电机平时全程 0；`reserve[1]` 一直是 507/508，不是错误码，不读。本地：`?mock&err` 或 `GO2W_FAKE_MOTOR_ERR=0,4,…（16 个）dev/run.sh`。

**力矩**读同一帧的 `motor_state[i].tau_est`（float32，N·m，电机估计值，字节 `4 + 92 + 48·i`），状态里在 `motorInfo.tau`；显示带正负（= 方向）、一位小数，|τ| < 0.5 变灰，不设报警线（不知道 Go2W 各关节的力矩上限）。录包核对：站着时小腿约 +7、左右髋符号相反（±4~7），轮子 ±2 以内。平时 lowstate 每 5 s 读一次，表开着且选「力矩」时网页发 `{t:'motor_fast', on:true}`，后端改成每 0.5 s 读一次（状态 2 Hz 推送），所有网页都关掉后恢复。

**过热自动趴下（11-18）**：16 个电机（12 个腿关节 + 4 个轮子）任何一个 ≥68 ℃，而狗站着（FixStand / Velocity），后端就自动趴下：和手动「趴下」同一流程（先取消任务、上锁、等停稳），不管有没有「保持站立」或任务；失败每 5 s 重试。还在 68 ℃ 以上时不让站起。网页提醒变成「电机过热，已自动趴下」。阈值 `go2w_web.py` 的 `MOTOR_HOT_LIE`，环境变量 `GO2W_MOTOR_HOT_LIE` 可改，0 = 关掉；状态里 `ctrl.hotLie` 是当前阈值。温度每 5 s 读一次，所以最多晚约 5 s；读不到温度（下面这条）时不起作用。本地：`GO2W_FAKE_MOTOR_TEMP=49,70,…（16 个）dev/run.sh`。

注意：`/go2w/robot_lowstate` 只在导航 / 建图档位运行时有人发，什么都没开时电量、电机温度都显示 `--`。

这一块 4 Hz 重绘，只在内容变了才改 DOM——下拉框展开时改它的选项或选中值，Chrome 会重建弹出列表，闪个不停（策略下拉框同理）。

## 建图自动保存（11-17）

建图时每 30 s（`GO2W_AUTOSAVE_SECONDS`）、停止建图前、雷达 / FAST-LIO / 里程计出问题时（两次至少隔 5 s），把当前地图存成 `data/maps/autosave_<建图开始时间>`，同一次建图覆盖同一份；地图没变就不存，单次存图耗时超过周期的 1/10 自动拉长间隔。只留最近 3 次建图的自动保存，旧的挪进 `data/maps/.trash`（14 天）；只认网页自己起的名字 `autosave_MMDD_HHMMSS(_prev)`，被路线引用、正在用、续建正在拿来当基准或目标的不动（v1.0.7）。测试：`dev/test_autosave.mjs`。

## 地图编辑（v1.0.2，11-18）

地图工具栏「编辑」（快捷键 6）打开编辑面板，编辑的是当前显示的、已经保存在 `data/maps` 里的地图；建图运行时不能编辑（地图还在变）。

- **去噪**：找孤立的小障碍块（8 邻域连通，格数 ≤ 滑块值，默认 4 格 = 10×10 cm 以内），先在地图上标红，点「去掉」才改。每块看周围一圈：空地多就擦成空地，未知多就擦成未知（射线尽头、楼外的零星点）。lab_20261116_c1 上 4 格能找到 479 块 / 726 格。
- **画笔**：擦成空地 / 画墙 / 擦成未知，笔刷直径 5–205 cm。画墙只用来补真实存在的墙：AMCL 拿激光和地图比，画一堵不存在的墙会干扰定位；想禁止通行要用 Nav2 禁行区（keepout，还没做）。
- **裁剪**：拖一个框，框外全部变成未知，用来去掉伸到楼外的射线。
- 撤销 / 重做（Ctrl/⌘+Z、Ctrl/⌘+Shift+Z，最多 40 步）、「按住看原图」。

保存只能**另存为新地图**（默认 `原名_e1`，同名拒绝），原图不动。网页只发「改了哪些格」（`[起点, 长度, 新值]` 段，下标按 OccupancyGrid 平铺）和它编辑时那张图的 CRC32；后端 `server/mapedit.py` 用硬盘上的原图算 CRC，对上了才改，只改动到的像素（254 / 0 / 205，按这张图的阈值和 negate 核对），其余字节和 yaml 照抄（只换 `image:`），写完按 map_server 规则读回来逐格核对。新图带 `meta.json`：`tool: web-edit`、`parent`、改了几格、去噪 / 画笔 / 裁剪次数、网页版本。可选把原图上的任务改到新图（有任务正在执行时不改）、保存后直接切换过去（导航在跑时会取消导航，切换后要重新定位）。

编辑后的图没有 slam_toolbox 的 `.posegraph` / `.data`，**不能当续建基准**：续建前置检查会提示用原图续建；续建一张有编辑版本的原图时提醒「编辑不会带到新图上，续建完要重新编辑」。

## 续建扫描闸门（v1.0.5，11-19）

## 摔倒 / 里程计发散保护（v1.0.6，11-19）

起因：11-19 .30 建图时摔倒，FAST-LIO 发散，自动保存把好图覆盖成了 467 × 551 m 的坏图。

- safety 循环 5 Hz 检查：运控不是网页让的、从 FixStand / Velocity 掉到 Passive（摔倒或遥控器趴下；网页刚让趴下后 3 s 内不算）→ 异常「意外趴下」；`/odom` 速度 > 4 m/s、角速度 > 8 rad/s 或相邻两条位置跳 > 1 m → 异常「里程计异常」。两种都自动存回溯包。
- 建图中出现任一种，立刻**冻结建图**：关扫描闸门（地图停在这一刻）、暂停自动保存（最近一份好的不会被覆盖）、暂停续建采集；停止建图时也不再「停止前保存」。
- 自动保存每次覆盖前把上一份留成 `<名字>_prev`（四件套齐，可以拿来续建）。
- 「保存地图」步骤显示冻结原因和保留的是哪一份。只是正常趴下、地图没乱：站起来后可以点「继续建图」；里程计飘过的不允许继续，只能停止后从保留的图续建。
- 异常后马上停止档位时，先把回溯包存掉再停。

测试：`dev/test_fall_guard.mjs`（准备见文件头：`GO2W_AUTOSAVE_SECONDS=4 GO2W_FAKE_MAP_GROW=1 dev/run.sh`）、`dev/test_autosave.mjs`。

## 地图显示方向

建图时地图的 x 轴取机器人开始建图那一刻的朝向，所以有的图是斜的、有的是竖的。这不影响定位和导航（Theta* 能走任意角度的直线），只是看着别扭。网页可以按地图单独保存一个**显示方向**：只转画面，不改地图坐标，所以路线、巡逻点、初始位姿都不用重做。

- **自由旋转：** 按住 Shift 拖动地图，或按住右键拖动，地图绕画面中心转。靠近 0° / 90° / 180° / 270°（±3°）会自动吸附，按住 Alt 不吸附。
- **指南针按钮：** 在地图右上角，红色针尖指向地图坐标的 +y 方向。单击顺时针转 90°，双击复位到 0°。
- **精确对齐：** 在「地图与录包」面板点「沿墙选两点」，选同一段长直墙上的两个点（至少 0.5 m，推荐 1 m 以上），可切换「对齐水平 / 对齐竖直」；「复位方向」回到 0°。
- **保存：** 松开鼠标后存到扩展坞的 `data/map_views.json`，按地图名记录，0° 不记录。从 166 和 142 打开、换哪台电脑看到的都一样，有人改了其他网页会跟着变。切换地图时自动换成那张图的方向，断线重连、切换档位不会清除。
- **建图时：** 还没有地图名，方向先暂存在 `_mapping` 下。「保存当前地图」时带给新地图。
- 地图、机器人、点云、路线、目标一起旋转，背景网格保持水平；鼠标点击换算回地图坐标，位姿读数仍是地图坐标。键盘遥控 W/S/A/D 相对机器人本身，不受影响。

**导出对齐地图（一般不需要）：** 建图运行时，输入新地图名并点击「保存对齐地图」。后端先保存原图及 SLAM 数据，再按当前显示方向把图片转正，生成 `<名字>_aligned.pgm/.yaml/.png`，都位于扩展坞的 `~/go2w/data/maps`。图片最多转 ±90°，剩下的 180° 记成新地图的显示方向。对齐副本的坐标和原图不同：用它导航要重新设置初始位姿、重新选路线站点。原图保留用于续建。导出失败时原图保留，可以重试；已有文件不会被覆盖。只在需要地图文件本身是正的时候才用（比如给 RViz 或别的工具）。

`dev/test_map_alignment.py` 验证图片旋转、原点和未知区域；本地假 ROS 页面也会运行相同的导出程序，可在未连接机器狗时检查保存结果。

### P1 的安全规则

- **急停**：取消所有导航目标（包括 RViz、patrol 发的）并调用 `/go2w_cmd_bridge/arm(false)`，cmd_bridge 会立即发 StopMove 并上锁。急停是锁存的：解除之前拒绝解锁和发目标；急停期间如果底盘被别处（比如 `nav.sh arm`）解锁，后端会再次上锁。解除急停后底盘仍保持上锁。
- **心跳**：网页每 0.5 s 发一次心跳（放在 Web Worker 里，切换浏览器标签页不会误触发）。最近一个发过运动相关指令（解锁、目标、取消、急停）的网页是「控制方」。控制方心跳超过 1.0 s 或网页关闭时，如果底盘解锁着或有导航目标，后端会取消导航并上锁，恢复后也不会自动解锁。超时时间用后端参数 `--heartbeat` 调整。
- 后端（`go2w_web` 容器）本身挂掉时没有人替它上锁：Nav2 和 cmd_bridge 会照常运行，这时请用遥控器。
- 暂停在真机上不支持（Nav2 没有暂停），用取消或上锁代替。

## 回溯录制

包名前缀是**狗编号**（11-12 起；下面写的 `go2w_` 是更早的叫法），比如 `go2w-01_1118_101500`。11-18 起狗编号按这个顺序取：狗硬盘上的 `/opt/go2w/config/runtime.env`（容器里 `/etc/go2w/runtime.env`）里的 `GO2W_ROBOT_ID` → 进程环境变量 `GO2W_ROBOT_ID` → 默认 `go2w-01`。每只狗在自己的 runtime.env 里写，不放进镜像或网页包；每次录包时现读，改了不用重启。格式：字母或数字开头，只能有字母、数字、`_`、`-`，最多 30 个字符，写错了用默认值并在启动日志里说明。启动日志会打「狗编号 go2w-01（来自 …）」。后端代码里用 `robot_id()` 取。

网页「开始录包」是分段录制（主仓库的 `scripts/segment_recorder.py`，替代原来的 `ros2 bag record`）：一直录，每 30 秒存成一个独立的包，包名是这一段的开始时间 `go2w_<月日>_<时分秒>`（同一秒重名加 `_2`；11-12 前是 `web_`）。每一段开头都写入 `/map`、`/tf_static`、`/robot_description` 这种只发一次的 topic，任何一段单独拿出来都能回放；段与段之间不丢消息。正在写的那段在 `data/bags/.recording/`，写完才整体移进 `data/bags`，所以列表里的包都能直接上传、删除。停止录包时把当前这段写完再退出。上次异常退出没写完的段会被移成 `<名字>_unfinished`（缺 metadata.yaml，用 `ros2 bag reindex` 修复）。段长在 `procs.py` 的 `BAG_SEGMENT`；日志 `data/logs/bag_go2w_<时间>.log`。命令行 `nav.sh` 手动跑的 `ros2 bag record` 仍按一个包处理。

录包区的「回溯录制」打开时（默认打开），建图 / 定位 / 导航运行期间，主仓库的 `scripts/rollback_recorder.py` 把最近 20 秒的数据留在内存里循环覆盖，不写硬盘；点「保存刚才 20 秒」存成 `data/bags/go2w_<时间>`（11-12 前是 `snap_`），和普通录包一样可以上传、删除。11-12 起录所有 topic（运行容器的入口脚本加 `--all`）。它是独立进程、独立节点，可以和 `ros2 bag record` 同时运行。`/map`、`/tf_static`、`/robot_description` 这种只发一次的 topic 会一直保留，放在包的开头。日志在 `data/logs/rollback.log`，开关状态在 `data/rollback.json`。

卡住自动保存：回溯录制在跑时，如果导航目标还没结束（没到、没取消）、底盘已解锁、没急停，而 odom 位置 8 秒内移动不到 8 cm、朝向变化不到 0.15 rad（约 9°），就认为狗卡住了，网页日志报一条警告，再等 15 秒，把判定卡住那一刻的前 15 秒 + 后 15 秒（共 30 秒）存成 `data/bags/go2w_<时间>`（11-12 前是 `stuck_`；网页日志里会写明是卡住自动保存）。回溯进程因此缓存最近 30 秒；手动「保存刚才 20 秒」仍是 20 秒。同一次停住只存一个；两次自动保存至少隔 60 秒。阈值在 `go2w_web.py` 的 `STUCK_*`，等待秒数也可以用环境变量 `GO2W_STUCK_SECONDS` 改。

## 版本号（11-18）

`static/version.json` 是唯一的版本来源：`version`、`date`，以及 `notes`（每个版本的更新说明，最新的在前）。左上角显示页面自己的版本，点开是更新说明。后端启动时读同一个文件（日志「网页版本 v1.0.1」），在状态里发 `webVersion`，并提供 `/version.json`；页面版本和后端不一样（机器狗升级了但页面没刷新）时，版本号变黄，提示刷新。

- v1.0.0 = 之前的 web-20261117-r25；v1.0.1 起用正式版本号，扩展坞上的包叫 `web-v<版本>`。
- 修 bug、小改动加第三位（v1.0.2），加功能加第二位（v1.1.0）。
- **每次发包都要改 `version.json`**：改 `version` 和 `date`，在 `notes` 最前面加一条。

## 部署到扩展坞

V1.0.0.1（11-13）起网页不再打包在运行镜像里，而是扩展坞上的独立网页包：`/opt/go2w/web/releases/<名字>/{server,static,tools}`，`/opt/go2w/web/current` 指向正在用的那个（运行容器只读挂载这个目录）。更新时把新包放进 `releases/`，改 `current` 链接，再 `sudo /opt/go2w/go2w web stop` / `web start` 只重启网页后端。只改前端时刷新页面就生效。后端的上传目标、信任的代理等环境变量以 `/opt/go2w/config/runtime.env` 为准（`web start` 时传进去，会覆盖代码里的默认值）。原来的 `sync.sh dock` + `docker compose up web` 是给 `go2w_humble` / `go2w_web` 用的，现在不能再用。

打开网页 · 在 Mac 浏览器里：http://192.168.1.21:8080

## 常驻服务器入口（192.168.1.22）

大家平时打开 **http://192.168.1.22**。22 上的 nginx 提供前端页面，并把 `/ws` 转发到扩展坞的 `192.168.1.21:8080`。后端、心跳上锁和进程管理仍在扩展坞上，22 只做转发。机器人关机时页面仍能打开，但只显示「机器人未连接」，开机后自动重连。直接打开 `http://192.168.1.21:8080` 也照常能用。

- 第一次安装（已完成 11-05）· 在 22 上运行：`sudo bash ~/go2w-web-setup/install.sh evoengine`（文件来自主仓库 `scripts/server/`）。安装 nginx 并设为开机自启，放行局域网访问 80 端口，禁止系统休眠。
- 改了前端 · 在 Mac 上运行主仓库的 `scripts/sync.sh server`。前端在扩展坞上也有一份，要保持一致。
- 后端只信任来自 22 的 `X-Forwarded-For`，日志显示为「真实 IP 经 192.168.1.22」。代理地址可以用环境变量 `GO2W_TRUSTED_PROXIES` 修改，多个地址用逗号分隔。

看后端日志 · 在扩展坞上运行：

```bash
docker logs -f go2w_web
```

只改了后端代码时重启 · 在扩展坞上运行：

```bash
docker restart go2w_web
```
